Domain 1: Development with AWS Services — 32%

The biggest slice of the exam: ~16 of the 50 scored questions. Its centre of gravity is Lambda and DynamoDB. If you master only one domain, make it this one.

Reference — revisit often ~16 scored questions Print-friendly
What this domain actually asks In AWS's own words, three tasks: (1) write code for apps hosted on AWS, (2) write code for Lambda, (3) use data stores (especially DynamoDB). In practice: Lambda + DynamoDB + API Gateway + messaging (SQS/SNS/EventBridge/Kinesis). Those four are 80% of this domain.

1. AWS Lambda — the heart of this domain

Think of Lambda like a light switch. You don't leave the bulb on 24 hours — you flip the switch, you get light, the job's done, switch off. You're billed only for the time the light was on. EC2 is a generator running all night whether you're in the room or not.

Lambda numbers — memorise these
  • Timeout: max 900 seconds = 15 minutes. ⭐ The #1 exam number. Work longer than 15 min = Lambda is wrong, Fargate is right.
  • Memory: 128 MB to 10,240 MB (10 GB). CPU scales with memory — you cannot set it separately. 1,769 MB = exactly 1 vCPU.
  • /tmp ephemeral storage: 512 MB to 10,240 MB. Default is 512 MB. This is disk space for large files.
  • Deployment package: 50 MB zipped, 250 MB unzipped (including layers). Container image: 10 GB.
  • Payload: 6 MB synchronous (request and response each), 256 KB asynchronous. Response streaming: 200 MB.
  • Environment variables: 4 KB total. This is why large secrets go in Secrets Manager, not env vars.
  • Layers: 5 per function. Concurrent executions: 1,000 default per region (can be increased).

Lambda concurrency — an exam favourite

Concurrency means: how many copies are running at the same moment. Restaurant analogy: if each customer takes 3 minutes and 10 arrive per minute, you need 30 tables. The formula is the same:

Concurrency = requests per second × average duration (seconds)

TypeWhat it doesWhen it's the exam answer
Reserved concurrency Reserves slots for one function — and also caps it at that number. Two jobs at once. "One function is eating everyone's concurrency" or "protect a downstream database from being overwhelmed". Does NOT fix cold starts.
Provisioned concurrency Keeps execution environments pre-warmed and ready. You pay even with zero requests. ⭐ Any mention of "cold start" or "consistent low latency" = this is the answer. This is the cold-start CURE.
Trap — reserved vs provisioned These two names are very similar and AWS deliberately offers both as options. The memory hook: Reserved = a limit (how many can run at most). Provisioned = pre-warmed (kills cold starts). If the question says "cold start", the answer is always Provisioned.

Lambda error handling

  • Synchronous invoke (e.g. from API Gateway): NO automatic retries. The client gets the error; retrying is the client's job.
  • Asynchronous invoke (from S3, SNS): Lambda automatically retries 2 more times (3 attempts total). Still failing → goes to a DLQ or a Destination.
  • Lambda Destinations — the newer, better approach. Routes both success AND failure to a target (SQS, SNS, Lambda, EventBridge). A DLQ handles failure only.
  • Event source mapping (from SQS, Kinesis, DynamoDB Streams): Lambda polls. Retries happen at the batch level here.
Lambda + VPC — the exam always asks this
  • By default Lambda runs OUTSIDE your VPC — it has internet access, but cannot reach a private RDS.
  • To reach a private RDS, put Lambda in the VPC (give it subnets + a security group).
  • ⚠️ But the moment it's in a VPC, internet access disappears. To get it back: private subnet + NAT Gateway. For AWS services, better and cheaper: VPC endpoints.

2. DynamoDB — the second-biggest topic

Think of DynamoDB as a huge cabinet with thousands of drawers. The partition key tells you which drawer to open. The sort key tells you the order of things inside that drawer. If you know the drawer number, you get it instantly (Query). If you don't, you must open every drawer (Scan) — slow and expensive.

DynamoDB numbers
  • Max item size: 400 KB. ⭐ Bigger than that? Store it in S3 and keep only a pointer (the S3 key) in DynamoDB.
  • LSI: 5 per table — can ONLY be created when the table is created, never after. Same partition key, different sort key.
  • GSI: 20 per table (default) — can be added or removed any time. Completely different partition and sort key.
  • A single Query/Scan returns max 1 MB of data. Need more? Paginate.
  • 1 RCU = one strongly-consistent read of 4 KB/sec, OR two eventually-consistent reads. 1 WCU = one write of 1 KB/sec.

Query vs Scan — a guaranteed exam question

 QueryScan
What it doesGoes straight to one partition keyReads the ENTIRE table, then filters

On the examUsually the correct answerUsually the answer to "what's wrong with this app". Even with a FilterExpression it still reads the whole table — the filter applies AFTER the read, so it saves no cost.
Hot partitions — high-cardinality keys AWS made this task statement 1.3.1, so it will appear. The problem: if a partition key has few distinct values (like status = "active"), all traffic hits one partition — a hot partition — and throttling begins. The fix: choose a key with many distinct values (high cardinality) — like user_id or order_id. Cabinet analogy: if everything goes in one drawer, that drawer jams even though the other 999 are empty.

LSI vs GSI — the memory hook

  • LSI = Locked at creation. Cannot be added later. Same partition key. Shares the table's capacity. Can do strongly consistent reads.
  • GSI = Growable / anytime. Add whenever. Any keys. Its own separate capacity. Eventually consistent only — cannot do strongly consistent reads. ⚠️ If a GSI runs out of capacity, writes to the base table get throttled — a favourite exam trap.

Other DynamoDB features you need

  • DAX (DynamoDB Accelerator) — an in-memory cache for DynamoDB. Microsecond reads. "Reduce read latency with minimal code changes" = DAX. (ElastiCache requires code changes; DAX does not.)
  • DynamoDB Streams — a record of every change (insert/update/delete), retained 24 hours. Used to trigger Lambda. "Do something on every change" = Streams + Lambda.
  • TTL — automatically deletes items based on a timestamp attribute. It is free (consumes no WCU). "Automatically remove old data" = TTL.
  • Capacity modes: On-demand = unpredictable or spiky traffic, no planning, pricier per request. Provisioned = predictable traffic, cheaper, can add auto-scaling. "Unpredictable/spiky" in the question = On-demand.
  • Consistency: reads are eventually consistent by default (cheaper, half the cost). Strongly consistent must be requested and costs double the RCU. "Must read the value it just wrote" = strongly consistent.

3. API Gateway

  • Endpoint types: Edge-optimized (global users, via CloudFront), Regional (clients in the same region), Private (only inside a VPC).
  • Integration types: Lambda proxy (whole request passed to Lambda — most common), Lambda (transform via mapping templates), HTTP, AWS service, Mock.
  • Stages — separate deployments for dev/test/prod. Stage variables = per-stage config (e.g. which Lambda alias to call). This is task statement 3.4.10 — it appears on the exam.
  • Caching — at the stage level. Default TTL 300 seconds. Reduces backend load.
  • Throttling — default account limit 10,000 requests/second, burst 5,000. Usage plans + API keys give per-customer limits.
  • Authorizers: IAM (for AWS principals), Cognito (for app users), Lambda authorizer (custom logic / third-party tokens).
API Gateway timeout
  • Maximum integration timeout: 29 seconds. Lambda can run 15 minutes, but API Gateway gives up after 29 seconds. Hence the pattern for long work: API Gateway → SQS/Step Functions → Lambda (async), returning 202 Accepted immediately.

4. Messaging — which service, when

These four are often the four options in a single exam question. Knowing the difference is essential.

ServiceOne-line meaningTrigger words in the question
SQS A queue. One message, read by one consumer, then deleted. Buffers work. "decouple", "buffer", "absorb spikes", "don't lose work"
SNS Pub/sub. One message goes to MANY subscribers (fan-out). "notify multiple systems", "fan-out", "send email/SMS"
EventBridge An event bus with rules and filtering. Connects AWS services and SaaS apps. Can also schedule (cron). "event-driven", "route based on content", "schedule", "third-party SaaS"
Kinesis Data Streams Real-time streaming. Data sits in shards; MULTIPLE consumers can re-read it. Ordering guaranteed per shard. "real-time analytics", "clickstream", "IoT", "replay the data", "ordering required"
SQS numbers
  • Message retention: default 4 days, max 14 days. Minimum 60 seconds.
  • Max message size: 256 KB. Larger? Use S3 + the Extended Client Library.
  • Visibility timeout: default 30 seconds, max 12 hours. ⭐ If the consumer takes longer than this, the message returns to the queue and gets processed TWICE — the classic exam "duplicate processing" question. Fix: raise the visibility timeout or call ChangeMessageVisibility.
  • Standard queue = unlimited throughput, best-effort ordering, at-least-once delivery (duplicates possible). FIFO queue = guaranteed order, exactly-once, 300 msg/sec (3,000 with batching). "Order matters" or "no duplicates" = FIFO.
  • Long polling — ReceiveMessageWaitTimeSeconds 1–20 seconds. Reduces empty responses and cost. "Reduce empty responses / API call costs" = long polling.
A classic pattern to memorise SNS + SQS Fan-out. One event must reach several systems, each processing at its own pace, with no message lost. Solution: an SNS topic → with MULTIPLE SQS queues as subscribers → each queue with its own consumer. This appears repeatedly on the exam. SNS alone can drop a message if a consumer is down; putting SQS in between makes it durable.

5. Step Functions and S3 (smaller, but tested)

  • Step Functions — chains multiple Lambdas into a workflow as a visual state machine. Retries, error handling, parallel branches built in. "Orchestrate multiple steps" / "long-running workflow with error handling" = Step Functions. Standard workflows run up to 1 year; Express up to 5 minutes, for high volume.
  • S3 event notifications — trigger Lambda, SQS, or SNS on upload/delete. A common Domain 1 pattern.
  • S3 multipart upload — recommended above 100 MB, required above 5 GB. Max object size is 5 TB.
  • S3 presigned URLs — give someone temporary permission to upload/download one object without AWS credentials. "Let users upload directly to S3 securely" = presigned URL.

Django bridge All of this maps to your work. SQS = Celery + Redis/RabbitMQ. Same idea: take long work out of the request and put it on a queue. Visibility timeout is exactly Celery's visibility_timeout problem — if a task runs long, another worker picks it up again. DynamoDB Query vs Scan = Django's .filter() on an indexed column vs looping the whole table. That's the N+1 lesson again: go via the index, don't read the whole table. Lambda concurrency = Gunicorn workers — how many requests can be handled at once. The only difference is that AWS gives these different names.
