0. Exam reality — understand this first

Four facts that change your strategy
  • 65 questions, but only 50 count. Fifteen are experimental and unscored. The upside: if a question seems bizarre and impossible, it may well be one of those 15. Never let one hard question rattle you.
  • Pass = 720/1000, and scoring is "compensatory". You do not need to pass each domain — only overall. A weak Domain 4 with a strong Domain 1 still passes. Strengthen your strengths too, don't only chase weaknesses.
  • No penalty for a wrong answer. Blank and wrong score identically — both zero. So never leave a question blank. A guess among 4 is 25%; after eliminating 2, a guess is 50%.
  • 130 minutes ÷ 65 questions = 2 minutes each. Tight but sufficient. The real danger is spending 6 minutes on one question and then rushing 8 at the end.

1. Exam English — the most important section for you

AWS deliberately writes long questions. Often a 4-line story where only 1 line matters. And two of the four options are 90% identical — differing by a single word. That one word is the answer.

The 3-step method — use it on every question Step 1: Read the last line first. The actual question is always at the end ("Which solution will…"). Read it, then the story above. Now you know what you're looking for — it saves time and stops your attention drifting.

Step 2: Mark the qualifying word. MOST cost-effective / LEAST operational overhead / FASTEST. That word tells you more than one option works, but only one satisfies the constraint.

Step 3: Eliminate, don't select. Two options are usually clearly wrong (wrong service, or against AWS best practice). Cut them. Then compare the remaining two word by word — find the difference, and let the qualifying word decide.

Qualifying words — what they mean in exam language

Phrase in the questionWhat AWS actually meansLean towards
MOST cost-effective All options work. Pick the cheapest. Usually means: serverless, or a cheaper S3 storage class, or Spot instances. Lambda > EC2 · Spot > On-Demand · S3 > EBS
LEAST operational overhead
(or: LEAST management effort)		 ⭐ The most frequent phrase. It means "let AWS do the work, not you". Any option that makes you run servers, patch them, or write code is wrong. The managed service always wins. Fargate > EC2 · Secrets Manager auto-rotation > your own Lambda
MINIMAL / NO code changes Eliminate any option saying "modify the application". Look for a configuration fix, not a code fix. A config/infrastructure fix, not new SDK code
MOST secure Eliminate anything where credentials are written down anywhere. A role always beats a key. IAM role > access key · KMS encryption · least privilege
FASTEST / lowest latency The question is about caching or pre-warming. ElastiCache · DAX · CloudFront · Provisioned Concurrency
Highly available / fault tolerant It's about Multi-AZ. Every single-AZ option is wrong. Multi-AZ · multiple subnets · Auto Scaling
The biggest trap — the "90% correct option" AWS's favourite technique: an option that looks completely right but contains one wrong word. Examples: "Create an IAM user for the EC2 instance" (wrong — should be a role). "Store the key in an environment variable" (wrong — Secrets Manager). "Use a Local Secondary Index" on an existing table (wrong — an LSI can only be created with the table). So: read every option to the end. The first five words being right doesn't make the option right. This matters especially for you — when English is effortful, the brain reads a few words and declares "that's the one".

2. Guaranteed questions — these will almost certainly appear

These topics appear on essentially every DVA-C02 exam. Master only this section and you are very close to a pass.

G1. IAM policy evaluation — free points

Explicit DENY > Explicit ALLOW > Implicit deny (the default)

Meaning: if a single Deny exists anywhere, the answer is always "access denied" — even if ten policies say Allow. And anything not mentioned at all is denied (implicit deny). The exam shows you three policies and asks "can the user do this?" — just hunt for a Deny. Found one → the answer is no.

G2. Query vs Scan (DynamoDB)

The answer is almost always Query. Scan reads the whole table — expensive and slow.

If the question says "the application is slow" or "costs are high" and the code uses a Scan, the answer is: use Query, and if the right key isn't available for a Query, create a GSI. That two-step answer is an exam favourite.

G3. Lambda's 15-minute limit

Work longer than 15 minutes = Lambda is the WRONG answer. Fargate / Step Functions / Batch is right.

The exam hides this: "the processing job takes 45 minutes". The moment you see that, eliminate every Lambda option — however right they look.

G4. Deployment strategies

The question asks forAnswer
Zero downtime, instant rollbackBlue/Green
Test on a few users first, then everyoneCanary
Gradually shift everyone (in equal steps)Linear
Cheapest, downtime acceptableAll-at-once / In-place

G5. Where to put credentials

Never in code. EC2/Lambda = IAM role. Needs rotation = Secrets Manager. Needs cheap = Parameter Store.

4. Confusable pairs — where most marks are lost

AWS deliberately offers both options because the names sound alike. Each pair below has a memory hook.

PairThe difference — and how to remember it
Reserved vs Provisioned concurrency Reserved = a cap. Provisioned = pre-warmed. Hook: the words "cold start" → always Provisioned. Reserved does not fix cold starts.
LSI vs GSI L = Local = Locked. An LSI can only be created with the table, never after — and keeps the same partition key. A GSI can be created any time with any key. Hook: "existing table" or "already in production" in the question = the answer is GSI, because an LSI is no longer possible.
Secrets Manager vs Parameter Store Secrets Manager = costs money, but rotates automatically. Parameter Store = free (standard tier), but you build rotation yourself. Hook: "automatic rotation" → Secrets Manager. "cost-effective" + simple config → Parameter Store.
User Pool vs Identity Pool (Cognito) User Pool = who you are (sign-in). Identity Pool = what you may do in AWS (credentials). Hook: the User Pool is the door, the Identity Pool is the key. Sign-up/sign-in mentioned = User Pool. "access S3/DynamoDB directly" = Identity Pool.
SQS vs SNS vs Kinesis SQS = one message, one consumer, gone after reading. SNS = one message copied to all subscribers (fan-out). Kinesis = a river of data, many consumers, and you can re-read it (replay). Hook: "replay" or "analytics" only ever points to Kinesis.
CloudTrail vs CloudWatch CloudTrail = WHO did it (audit, API calls). CloudWatch = WHAT is happening (metrics, logs, alarms). Hook: a trail is footprints — whose steps were these. "Who" or "audit" in the question = CloudTrail.
SSE-S3 vs SSE-KMS vs SSE-C SSE-S3 = AWS manages the key, you do nothing. SSE-KMS = your own key, and every use is logged to CloudTrail. SSE-C = you send the key with each request. Hook: "audit key usage" or "control the key" = KMS.
CodeDeploy vs CodePipeline vs CodeBuild CodeBuild = compiles and tests. CodeDeploy = pushes to servers/Lambda. CodePipeline = the manager deciding which step runs when. Hook: Pipeline is only the orchestration — it builds nothing itself.

5. The numbers that get asked

The full list is on the Numbers sheet. These are the most frequently asked:

  • Lambda timeout: 900 seconds = 15 minutes. ⭐ The #1 exam number.
  • Lambda memory: 128 MB – 10,240 MB. CPU scales with memory. 1,769 MB = 1 vCPU.
  • Lambda payload: 6 MB sync, 256 KB async. Package: 50 MB zipped / 250 MB unzipped.
  • Lambda concurrency: 1,000 per region (can be raised). Env vars: 4 KB.
  • DynamoDB item: max 400 KB. Larger → store in S3, keep only the pointer in DynamoDB.
  • DynamoDB Query result: max 1 MB per call (then paginate).
  • SQS message: 256 KB. Retention: 4 days default, 14 days max. Visibility timeout 30 s default, 12 h max.
  • SQS long polling: max 20 seconds. This is the cost-reduction answer.
  • Kinesis: 1 MB/s in, 2 MB/s out per shard. Retention 24 h default, 365 days max.
  • API Gateway timeout: 29 seconds. ⭐ Lambda can run 15 minutes but API Gateway cuts it at 29 seconds — a very common trap.
  • S3 object: max 5 TB. Above 5 GB → multipart upload is required. Above 100 MB → multipart recommended.
  • The exam: 65 questions, 50 scored, 130 minutes, pass at 720/1000.

6. Exam-day plan

The two-pass method — this is what stops you running out of time Pass 1 (~85 min): go through all 65 once. If a question is clear within 90 seconds, answer it. If not — pick something anyway (never leave blank), hit "Mark for review", and move on. Getting stuck on one question is the biggest danger.

Pass 2 (~35 min): return only to the marked ones. There's less pressure now because everything already has an answer. Often a later question reminds you of an earlier answer.

Final 10 min: confirm nothing is blank. That's it. Don't keep changing answers — your first instinct is usually better, unless you've now spotted a word you missed.
The week before
  • Start no new topics. New content this late destroys confidence rather than building it.
  • Daily: 1 practice exam + 2 hours reviewing its wrong answers.
  • Five minutes daily: this page's trigger words table and the Numbers sheet.
  • The last night: nothing new. Only this page. Then sleep — sleep does more for recall than extra study does.

Test yourself — cover the page and answer

  • A question says "LEAST operational overhead". What is it actually asking?
  • A job takes 45 minutes. Why is Lambda wrong, and what's right?
  • The table is already in production and you need to query a new attribute. LSI or GSI? Why?
  • One policy says Allow, another says Deny. What's the result?
  • What answers "cold start" — Reserved or Provisioned concurrency?
  • A Lambda runs 3 minutes behind API Gateway. What breaks?
  • "Who deleted this S3 bucket" — CloudTrail or CloudWatch?
  • The exam has 65 questions but how many count? How should that change your strategy?
