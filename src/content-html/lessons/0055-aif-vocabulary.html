The language of AI: the words everything else stands on

This exam doesn't ask you to build AI — it asks whether you understand its language. You said AI is new to you, so this lesson starts from the ground. Nothing here assumes you already know an AI word.

~12 min One concept: the vocabulary everything rests on Win: read any AIF question without getting lost
If you remember one thing AI is the big circle. ML sits inside it. Deep Learning sits inside ML. GenAI sits inside Deep Learning. Each smaller circle is a kind of the bigger one — like: vehicle → petrol car → Honda → Civic.

And the distinction the exam asks for again and again:
Traditional ML predicts something — "will this customer leave or stay?"
GenAI creates something new — text, images, code.

"Predict", "classify", "forecast" in a question = traditional ML. "Generate", "summarise", "write", "chat" = GenAI.

The story: a new employee

Imagine training a new employee. Training is the period where they read thousands of past files and learn — expensive, slow, done once. Inference is the moment you ask them "what should we do with this customer?" and they answer — cheap, instant, happening constantly.

That difference is fundamental to the exam. Training = learning. Inference = using. When a question says "the model is in production and each request costs money", it's talking about inference. When it says "building the model was expensive and slow", that's training.

Now extend the story. A Foundation Model (FM) is an employee who has already read the world's libraries — you didn't train them, they arrived ready. Fine-tuning means teaching them your company's specific way of working. And RAG means handing them the key to your filing cabinet, so they consult your documents before answering.

The core words — you cannot read a question without these
  • ⭐ Model = the thing that learned from data and now gives answers. Algorithm = the method by which it learned. (Model = the cooked dish; algorithm = the recipe.)
  • ⭐ Training = learning from data (expensive, once). Inference = getting answers from the trained model (cheap, constant). Four kinds of inference: real-time (instant answer), batch (lots of data at once, later), asynchronous (large job, answer comes later), serverless (occasional use, no servers to manage).
  • ⭐ Token = a small piece of text (roughly ¾ of a word). Models read and write in tokens, and you are billed per token — the exam asks this. Longer prompt = more tokens = more cost.
  • ⭐ Embedding / vector = turning text into a list of numbers such that things with similar meaning end up numerically close. That's how search can work by meaning rather than exact words. It's the foundation of RAG.
  • Chunking = splitting a large document into smaller pieces so they can be embedded and searched.
  • ⭐ Hallucination = when the model states something false with complete confidence. GenAI's biggest weakness and a recurring exam topic. The cures: RAG (give it real documents) and human review.
  • Foundation Model (FM) = a large, pre-trained model that can do many tasks. LLM = the text-focused kind of FM. Multi-modal = handles more than one data type (text + images). Diffusion model = the kind that generates images.
  • ⭐ Three kinds of learning: Supervised = learning from labelled data ("this email is spam, this isn't"). Unsupervised = finding patterns with no labels (clustering). Reinforcement = learning by trial and reward (like playing a game). "Labelled data" = supervised; "grouping without labels" = unsupervised.
  • Agentic AI / AI agent = a model that doesn't just answer but takes actions — using tools, working in multiple steps. MCP (Model Context Protocol) = the standard by which agents connect to external systems. (New, and named explicitly in the exam guide.)

Three ways to make a model do your job

This is the exam's most important decision (Domain 3, 28% — the largest domain). Three approaches, differing in cost and freshness of data:

ApproachWhat it isCostWhen it's the answer
Prompt engineering
just asking better		 Giving the model better instructions. The model itself is unchanged. Cheapest Always try this first. "Lowest cost" or "no training required" = this.
RAG ⭐
show it your files		 Before answering, the model searches your documents and answers from them. The model isn't changed — it's just given information. Medium ⭐ "company's own data", "up-to-date information", "reduce hallucinations", "cite sources" = RAG, always. The most frequently correct answer in this domain.
Fine-tuning
retrain the model		 Retraining the model on your data. The model genuinely changes. Expensive When you need to change style, tone or format, or teach a specialist domain (medical, legal). Not for fresh information — that's RAG's job.
The exam's biggest trap — RAG vs Fine-tuning These two options appear together in almost every question, and people choose wrong. The easy way to hold the difference:

RAG = giving the model new INFORMATION. (what it knows)
Fine-tuning = changing the model's MANNER. (how it speaks)

If company policy changes monthly, fine-tuning is foolish — you'd retrain every month. With RAG you just replace the document and the model stays as it is. So "frequently changing" or "latest" = RAG, never fine-tuning.
Exam English — the vocabulary of AI questions "infer" / "inference" = getting an answer from a model. (In ordinary English, "to conclude".)
"prompt" = the instruction or question you give the model.
"hallucination" = a confident falsehood from the model.
"ground truth" = the real, correct answer used to judge the model.
"bias" = unfair skew (treating some group wrongly).
"overfitting" = the model memorised the training data and fails on new data. "underfitting" = it barely learned at all.
"explainability" / "interpretability" = being able to see why the model gave that answer.
"guardrails" = safety limits stopping the model saying harmful things.
"curated" = carefully selected and cleaned (data).
"modality" = the type of data (text, image, audio).
⚠️ AIF has question types CLF does not CLF has only two types (multiple choice and multiple response). AIF has four — and the two extra ones are harder:

Ordering: put 3–5 items in the correct sequence. Matching: pair 3–7 items correctly.

⚠️ Neither gives partial credit — all correct or zero. So the AI/ML lifecycle order (data → training → evaluation → deployment → monitoring) and what each service does must be exactly clear.

Good news: these questions are short to read — no long English paragraphs. That works in your favour.

Bridge to your Django work AI is new, but the shapes aren't. Try it this way:

Embeddings + vector search is a database index. Without an index you scan the whole table (slow); with one you jump to the row. Vector search is the same idea, but matching on similar meaning instead of equality. If you've used Postgres full-text search, this is the next step from it.

RAG is, to you, a SELECT query whose result you paste into the prompt. There's no magic — the model is handed the text your query found. That's exactly why RAG is the right answer to "fresh data" questions: the query runs every time.

Training vs inference = migrate vs runserver. One is heavy, once, at deploy time. The other is light, on every request.
From memory, without scrolling up: training vs inference? When RAG, when fine-tuning? What is a hallucination and its cure? And what's learning from labelled data called?
Training = learning (expensive, once); inference = using (cheap, constant). RAG = new information (fresh data, your documents); fine-tuning = new manner (style, tone, specialist domain).
