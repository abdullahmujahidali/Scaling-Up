High availability = multiple Availability Zones. EBS = one instance's disk (one AZ); EFS = a shared file system for many instances. CloudFront = the CDN, content near users. Today we close the remaining gaps.

⭐ The EC2 details not yet covered
  • ⭐ AMI (Amazon Machine Image) = a snapshot-image of a whole server, used to launch identical new instances. Think of setting up one laptop perfectly, taking an image of it, then building ten more from that image. "Quickly launch pre-configured servers" = AMI.
  • ⭐ EBS snapshot = a backup of a disk, stored in S3. A new volume can be created from it — including in another AZ or Region. (Remember: an EBS volume lives in one AZ, but a snapshot is how you move it.)
  • EC2 user data = a script that runs automatically the first time an instance boots (installing software and so on). It runs on first boot only.
  • Elastic IP = a fixed public IP address you own, which stays the same even if you stop and start the instance. (Otherwise you get a new IP each time.)
  • Scaling policies = the rules telling Auto Scaling when to grow or shrink. Dynamic = react to current load (e.g. CPU above 70%). Scheduled = by clock (e.g. every Monday morning). Predictive = forecast from past patterns.
⭐ The remaining S3 points
  • ⭐ S3 Versioning = keeping previous copies of every object, so an accidental delete or overwrite can be recovered. "Protect against accidental deletion" = versioning.
  • S3 Transfer Acceleration = faster uploads of large files from far away, routed through CloudFront's edge locations.
  • The full storage-class order (dearest to cheapest storage): Standard → Intelligent-Tiering (AWS decides for you) → Standard-IA → One Zone-IA (cheaper, but only one AZ) → Glacier Instant → Glacier Flexible → Glacier Deep Archive (cheapest, retrieval takes hours).
⭐ Savings Plans (Domain 4 — this does get asked)
  • ⭐ Savings Plans = savings like Reserved Instances but more flexible. The difference: with Reserved you commit to a specific instance; with a Savings Plan you commit to spend — "$X per hour for 1 or 3 years".

    Compute Savings Plan = up to 66% (most flexible — covers EC2, Fargate and Lambda, any Region or instance family).
    EC2 Instance Savings Plan = up to 72% (less flexible — one family in one Region — but a bigger discount).

    "Flexibility" in a question = Compute; "maximum discount" = EC2 Instance.
The remaining management & governance services
  • AWS PrivateLink = connecting two networks privately inside AWS, without traffic crossing the internet. "Data must not traverse the internet" = PrivateLink. AWS Audit Manager = continuously collecting evidence for an audit. (Hold the difference: Artifact = downloading AWS's own compliance reports; Audit Manager = gathering evidence for YOUR audit.)
  • AWS Service Catalog = a list of company-approved templates, so teams can only create what IT has sanctioned.
  • AWS License Manager = tracking how many software licences (Windows, Oracle and so on) are in use.
  • AWS Well-Architected Tool = a free tool that asks questions about your workload and reports where it falls short of the six pillars. (The Framework is the principles; the Tool checks against them.)
  • Service Quotas = viewing service limits (such as how many EC2 instances) and requesting increases.
The remaining migration & hybrid services
  • AWS Migration Hub = tracking all migrations in one place. AWS Application Discovery Service = finding and assessing your on-premises servers before migrating. Migration Evaluator = estimating what a migration will cost.
  • AWS Elastic Disaster Recovery = recovering entire systems into AWS after a failure. AWS Local Zones = small AWS deployments near large cities for very low latency. AWS Wavelength = AWS inside 5G networks, for the lowest latency to mobile users.
The remaining AI/ML services (CLF needs recognition only)
  • Amazon Forecast = predicting future values (sales, demand). Amazon Personalize = recommendations ("customers also bought"). Amazon Fraud Detector = identifying fraudulent activity.

    All three are covered in depth in your AIF track — on CLF the name and its job is enough.
Exam English — words from this lesson "image" (as in AMI) = a complete copy of a server, not a picture.
"snapshot" = a saved copy of something at one moment.
"provision" = to set up a resource.
"quota" / "limit" = a cap.
"on-premises" = in your own data centre.
"disaster recovery" = restoring systems after a major failure.
"approved" = sanctioned in advance (appears in Service Catalog questions).
"retrieval" = getting data back out of an archive.

Bridge to your work An AMI is a Docker image. You build an image from a Dockerfile, then run ten containers from it rather than installing everything each time. An AMI is the same idea for a whole server.

An EBS snapshot is your pg_dump — a saved copy from one moment that you can restore later.

S3 versioning is git. The old copy is always there, and a mistake can be undone.

User data is the startup script you'd put in a Dockerfile RUN line or entrypoint.
