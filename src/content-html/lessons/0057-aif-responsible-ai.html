If you remember one thing The same Shared Responsibility Model applies to AI. AWS secures the model and the infrastructure; your data, your prompts, and the consequences of the model's decisions are yours.

And the four questions responsible AI keeps asking:
Is it fair? → bias → SageMaker Clarify
Could it say something harmful? → safety → Bedrock Guardrails
Can we explain why? → explainability → Clarify + Model Cards
Is a human watching? → oversight → Amazon A2I

The story: a new employee who makes decisions

Remember the employee from I1. Now imagine you've given them authority to approve loans. Four questions arise immediately — and they're exactly the four the exam asks.

1. Are they rejecting people from a particular group without cause? (bias / fairness) 2. Might they say something offensive to a customer? (safety / guardrails) 3. If someone asks "why was my loan refused?", can they give a reason? (explainability) 4. Is a senior reviewing the big decisions? (human in the loop)

And a fifth question specific to AI: sometimes they state falsehoods with total confidence (hallucination). The cure isn't scolding them — it's showing them the real file (RAG grounding) and checking the answer (output validation).

⭐ Domain 4 — responsible AI terms and their answers
  • ⭐ Bias = the model treating a group unfairly. Fairness is the goal. The cause is usually the training data — if the data was skewed, the model learns the skew. Answer: SageMaker Clarify + better (balanced, diverse, curated) data.
  • ⭐ Overfitting = the model memorised the training data; excellent on it, poor on new data. Underfitting = it barely learned; poor everywhere. This pair gets asked.
  • ⭐ Transparency = being open about the model (what data, what intended use) → SageMaker Model Cards. Explainability = understanding why a decision happened → Clarify. These are two different things.
  • The responsible-AI qualities the exam lists: fairness, inclusivity, robustness, safety, veracity (truthfulness), transparency, privacy, governance.
  • Legal risks of GenAI the exam names: intellectual property infringement claims, biased outputs, hallucinations, and loss of customer trust.
⭐ Domain 5 — security and governance (where CLF pays off)
  • ⭐ You are already studying these for CLF: IAM (roles, policies, who has access), encryption (at rest = stored data, in transit = data in motion), the Shared Responsibility Model. AIF asks them the same way, just in an AI setting. This is the real benefit of taking both together.
  • Amazon Macie = finding PII (personal data) in S3. AWS PrivateLink = a private connection that never crosses the internet. "Data must not traverse the internet" = PrivateLink.
  • ⭐ Prompt injection = a user hiding instructions in their input to hijack the model ("ignore your previous instructions and…"). This is AI's signature security weakness. Defences: input validation, output filtering, Guardrails.
  • Data leakage = private or confidential information appearing in the model's output. Toxicity = harmful or abusive language. Both are addressed by Guardrails and output filtering.
  • ⭐ Curing hallucinations (a favourite): RAG grounding (anchor answers in real documents), output validation, confidence scoring, and human-in-the-loop. "Write a better prompt" alone is rarely the full answer.
  • Governance tools the exam lists: CloudTrail (who did what — audit), AWS Config (tracking resource configuration), Audit Manager (preparing audits), AWS Artifact (downloading AWS's compliance reports), Amazon Inspector (finding vulnerabilities), Trusted Advisor.
  • Data lineage / cataloging = recording where data came from and what happened to it. Data residency = which country or Region the data is held in (a legal constraint). Generative AI Security Scoping Matrix = an AWS framework named explicitly in the exam guide.
The pair most often confused — Guardrails vs Clarify Both keep AI "in line", so they appear together as options. The difference is clean:

Bedrock Guardrails = a guard on the model's MOUTH. What it may and may not say. Forward-looking — it stops bad output before it appears. For GenAI.

SageMaker Clarify = an audit of the model's DECISIONS. Is it fair, and why did it decide that? Backward-looking analysis. More for traditional ML.

The phrase to hold: Guardrails stops it speaking; Clarify explains why it spoke.
Exam English — the language of governance and security "mitigate" = reduce or soften (a risk). Questions often ask "how to MITIGATE this risk".
"audit trail" = the record of who did what, when.
"lineage" = ancestry — where the data came from.
"residency" = which place or country the data lives in.
"retention" = how long data is kept.
"at rest" / "in transit" = stored data / data in motion.
"adversarial" = deliberately hostile (an attack).
"grounding" = anchoring answers in real source information.
"veracity" = truthfulness.
"robustness" = holding up well under difficult conditions.

Bridge to your Django work Prompt injection is SQL injection — and you already understand that one. In SQL injection the user writes SQL into their input and changes your query's meaning. In prompt injection the user writes instructions into their message and changes the model's instructions. The defence is the same instinct: never trust user input, never treat it as instructions, and validate what goes out too.

Audit trails are your Django logs and django-auditlog — CloudTrail does the same thing at the AWS level.

And "human in the loop"? That's your admin approval workflow. You've surely built a feature where something doesn't take effect until a person approves it. AI uses the identical idea — it's just called A2I.
From memory: what is prompt injection and its defence? The commonest cause of bias? Guardrails vs Clarify? And the real cure for hallucinations?
Prompt injection = hidden user instructions hijacking the model; defence = input validation + output filtering + Guardrails (the SQL-injection instinct). Bias comes from the training data. Guardrails stops it speaking (safety, forward); Clarify explains why it spoke (fairness/explainability, backward). Hallucinations are cured by RAG grounding + output validation + human review — not by temperature. All four? Then Domains 4 and 5 — a full 28% — are under control.
