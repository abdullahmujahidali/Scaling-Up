If you remember one thing This domain is about recognition, not memorisation. One sentence per service is enough — the exam never asks "what is EBS's maximum IOPS". It asks: "the company has this problem, which service?"

⭐ The three global-infrastructure words — these always appear:
Region = a geographic location (e.g. Mumbai), made of multiple AZs.
Availability Zone (AZ) = a separate data centre within that Region. High availability = use multiple AZs.
Edge location = a CloudFront cache point near users, so content arrives fast.

And: multiple AZs = high availability. Multiple Regions = disaster recovery, latency, or data sovereignty.

The story: cities, neighbourhoods and corner shops

Imagine a company's warehouses. A Region is a city — Karachi, Dubai, London. Availability Zones are separate warehouses in different neighbourhoods of that city: if one loses power or floods, the other keeps running. Hence multiple AZs = high availability.

Edge locations are small corner shops on every street — they don't hold full stock, just the popular items, so customers needn't travel to the city warehouse. That's CloudFront — keeping content near users.

And opening a warehouse in another city? That's multiple Regions — expensive, but necessary if a whole city floods (disaster recovery), if customers abroad need speed, or if the law requires data to stay in-country (data sovereignty).

⭐ Compute — services that run things
  • ⭐ Amazon EC2 = a virtual server in the cloud. Full control; you manage the OS. Instance families: compute optimized (more CPU), memory optimized (more RAM), storage optimized (more disk), general purpose.
  • ⭐ AWS Lambda = run code with no servers. Pay only while it runs. Max 15 minutes. "Run code without managing servers" = Lambda.
  • ⭐ AWS Fargate = running containers with no servers. Amazon ECS = AWS's own container orchestration. Amazon EKS = Kubernetes. Amazon ECR = the container image registry. "Kubernetes" = EKS, always.
  • AWS Elastic Beanstalk = give it your code and AWS provisions EC2, load balancing and scaling for you. "Deploy an app without managing infrastructure, but keep control" = Beanstalk. Amazon Lightsail = the simplest option, small sites at a fixed price. AWS Batch = large batch jobs. AWS Outposts = AWS hardware in your own data centre (hybrid).
  • ⭐ Auto Scaling = automatically adding/removing servers with demand (= elasticity). Elastic Load Balancer (ELB) = spreading traffic across servers. Together they provide high availability and elasticity.
⭐ Storage — where data lives
  • ⭐ Amazon S3 = object storage — files, images, backups, static website content. Reachable over the internet. Cheap and extremely durable (11 nines). "Store files/objects" = S3.
  • ⭐ Amazon EBS = block storage — a hard disk for one EC2 instance. Lives in a single AZ and normally attaches to one instance. "A disk/volume for an EC2 instance" = EBS.
  • ⭐ Amazon EFS = file storage — one file system many EC2 instances share simultaneously, spanning AZs. "A shared file system across multiple instances" = EFS. (Amazon FSx = for Windows or specialist file systems.)
  • Instance store = EC2's local disk — very fast but ephemeral (data is lost when the instance stops). "Temporary/scratch data" = instance store; "data must persist" = EBS.
  • S3 lifecycle policy = automatically moving older objects to cheaper tiers (Glacier). AWS Backup = centralised backup across services. AWS Storage Gateway = connecting your data centre to AWS storage (hybrid).
⭐ Databases — which one, when
  • ⭐ Amazon RDS = managed relational database (PostgreSQL, MySQL, etc.) — what your Django talks to. AWS handles patching, backups, replication. Amazon Aurora = AWS's own faster MySQL/PostgreSQL-compatible engine.
  • ⭐ Amazon DynamoDB = NoSQL, serverless, extremely fast at any scale. "NoSQL", "key-value" or "single-digit millisecond" = DynamoDB.
  • ⭐ Amazon ElastiCache = in-memory cache (Redis/Memcached) — reducing database load and improving speed.
  • Amazon Redshift = data warehouse (large-scale analytics). Amazon DocumentDB = MongoDB-compatible. Amazon Neptune = graph database (relationships).
  • AWS DMS = migrating databases to AWS. AWS SCT = converting the schema when changing engine (Oracle → PostgreSQL).
⭐ Networking and content delivery
  • ⭐ Amazon VPC = your own isolated network in AWS. Inside it: subnets (public = internet-reachable, private = not), an internet gateway, a NAT gateway.
  • ⭐ Security group vs network ACL (NACL) — a tested pair. Security group = guards the instance, stateful (return traffic is automatically allowed), allow rules only. NACL = guards the subnet, stateless, supports both allow and deny.
  • ⭐ Amazon CloudFront = the CDN — caching content at edge locations near users. "Reduce latency for global users" = CloudFront.
  • ⭐ Amazon Route 53 = DNS (domain names) + health checks + traffic routing. "Register a domain" or "DNS" = Route 53.
  • ⭐ AWS Direct Connect = a dedicated physical line from your data centre to AWS, bypassing the internet. Expensive but fast and consistent. AWS VPN = an encrypted tunnel over the internet — cheap and immediate. "Dedicated private connection" = Direct Connect.
  • AWS Global Accelerator = routing traffic over AWS's network for speed. AWS Transit Gateway = connecting many VPCs and networks centrally. Amazon API Gateway = creating and managing APIs.
The remaining named services
  • Messaging: Amazon SQS = a queue (messages wait; one consumer takes each). Amazon SNS = notifications, one message to many subscribers. Amazon EventBridge = triggering work from events. AWS Step Functions = multi-step workflows.
  • Analytics: Amazon Athena = SQL directly over S3. Amazon Kinesis = real-time streaming data. AWS Glue = ETL (cleaning and transforming data). Amazon QuickSight = dashboards and charts. Amazon EMR = big-data processing (Hadoop/Spark). Amazon OpenSearch = search and log analytics.
  • Management: AWS CloudFormation = infrastructure as code (build everything from a template). AWS Organizations = managing many accounts. AWS Control Tower = securely setting up many accounts. AWS Systems Manager = managing servers. Service Quotas = requesting limit increases. AWS Compute Optimizer = rightsizing recommendations.
  • Developer tools: CodeBuild (build), CodePipeline (CI/CD), X-Ray (tracing a request's journey). End-user computing: WorkSpaces (desktops in the cloud), AppStream 2.0 (streaming an application). Frontend: Amplify, AppSync. IoT: AWS IoT Core. Business: Amazon Connect (call centre), Amazon SES (sending email).
  • AI/ML (these appear on CLF too): SageMaker AI, Amazon Lex (chatbots), Amazon Kendra (intelligent search), Comprehend, Rekognition, Polly, Transcribe, Translate, Textract, Amazon Q. All covered in depth in your AIF track — this is the overlap between the two exams.
Exam English — Domain 3 vocabulary "provision" = create a resource. "deploy" = put into service.
"infrastructure as code (IaC)" = building infrastructure from templates (CloudFormation).
"programmatic access" = via code/CLI/SDK rather than the console.
"single point of failure" = the one thing whose failure stops everything. Why AZs are separate.
"durability" = the guarantee data won't be lost. "availability" = the guarantee you can reach it. Two different things.
"stateful" / "stateless" = remembers previous traffic / doesn't (security group / NACL).
"latency" = the delay before a response.
"ephemeral" = temporary, disappears (instance store).

Bridge to your work This domain is the most natural for you, because you touch these things daily. Your Django stack in AWS names:

gunicorn/Django → EC2 or Fargate. PostgreSQL → RDS. Redis → ElastiCache. Celery's queue → SQS. Media/static files → S3. nginx load balancing → ELB. Cloudflare → CloudFront. Domain DNS → Route 53.

So you've already built this architecture — the exam is asking for AWS's names for it. What's genuinely new is three words: Region, Availability Zone, edge location. Spend your time there and simply recognise the rest.
From memory: how do you get high availability? EBS vs EFS? Security group vs NACL? Direct Connect vs VPN? And what is CloudFront for?
High availability = multiple Availability Zones. EBS = one instance's disk in one AZ; EFS = a shared file system for many instances. Security group = on the instance, stateful, allow-only; NACL = on the subnet, stateless, allow and deny. Direct Connect = a dedicated physical line; VPN = an encrypted tunnel over the internet. CloudFront = the CDN, content near users. All five? Then the exam's largest domain (34%) is yours.
