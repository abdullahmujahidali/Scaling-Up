If you remember one thing Domain 1 (24%) is your cheapest domain, because it asks for no technical depth — only vocabulary. If you know what "IaaS", "elasticity" and "pilot light" mean, those questions take 20 seconds each. These are things to memorise, not to understand deeply.

1. IaaS, PaaS, SaaS — who manages how much

Everyday analogy Think of pizza. IaaS = you make it at home but rent the oven — dough, cheese, all your work. PaaS = the base arrives ready; you add toppings and bake. SaaS = the pizza is delivered; you just eat. The higher you go, the less you manage.
ModelYou manageAWS exampleTrigger words
IaaS — Infrastructure as a ServiceOS, patching, appsEC2"maximum control", "manage the operating system", "virtual machines"
PaaS — Platform as a ServiceOnly your codeElastic Beanstalk, Lambda"focus on code", "no infrastructure management", "deploy an application"
SaaS — Software as a ServiceNothing — just use itAmazon WorkSpaces, Gmail"ready-to-use software", "no installation"

The English of the exam "Manage the operating system" = IaaS = EC2. "Focus only on their code" = PaaS = Elastic Beanstalk. Those two phrases show up on the exam almost word for word.

2. Deployment models and the 5 characteristics

Three deployment models: Cloud/Public (everything on AWS), Hybrid (some AWS, some in your own data centre — triggered by the words "on-premises"), and Private cloud / On-premises (all your own). A question mentioning both an "existing data centre" and AWS = hybrid.

AWS lists 5 characteristics of cloud computing. Don't drill them — just recognise them: on-demand self-service (help yourself, no one to ask), broad network access (reach it from anywhere), resource pooling (all customers draw from one large pool), rapid elasticity (scale up and down instantly), measured service (pay for what you use).

Two words the exam confuses on purpose Scalability = the ability to handle more load (it can grow). Elasticity = growing and shrinking automatically with demand. "Automatically" or "scale down when demand drops" = elasticity.

Also: vertical scaling = making one machine bigger (t2.micro → t2.large). Horizontal scaling = adding more machines (1 server → 5). When the exam says "scale out", it means horizontal.

3. Copies: read replicas, Multi-AZ, DAX, Global Tables

There are four ways to copy a database, and the exam asks the purpose of each. The only difference: what the copy is for.

FeatureWhat it's forTrigger words
Read replica (RDS)Performance — extra copies to read from, spreading query load"too many reads", "reporting queries slow it down", "improve read performance"
Multi-AZ (RDS)Availability — a standby in another AZ, automatic failover"high availability", "automatic failover", "survive an AZ failure"
DAX (DynamoDB Accelerator)Speed — an in-memory cache in front of DynamoDB (microseconds)"DynamoDB" + "caching" / "microsecond"
Global Tables (DynamoDB)Geography — the same table live in several Regions"DynamoDB" + "multiple Regions" / "global users"
Aurora ServerlessUnpredictable load — capacity starts and stops itself"unpredictable", "intermittent", "don't want to manage capacity"

The most common trap Read replica vs Multi-AZ. Both are copies, but their purposes are opposite: read replica = performance, Multi-AZ = availability. If the question says "failover" or "an AZ fails", it's Multi-AZ. If it says reads are slow, it's a read replica.

The same logic for S3 replication: CRR (Cross-Region Replication) = a copy in another Region — for compliance, or users in another country. SRR (Same-Region Replication) = a copy in the same Region — aggregating logs, or copying production data into test.

4. The four disaster recovery strategies

The exam asks for these four by name. They differ on two things only: how expensive and how fast you recover. Top to bottom: cheap and slow → expensive and instant.

StrategyWhat's running in advanceCost / speed
Backup & RestoreNothing — only backups existCheapest, slowest (hours)
Pilot LightOnly the critical core (e.g. the database), switched off/smallCheap, fairly fast
Warm StandbyA full but small copy, already runningCostlier, fast (minutes)
Multi-Site / Hot SiteA full-size copy running liveMost expensive, instant
Everyday analogy Think of your home electricity. Backup & restore = there's a candle in a drawer; you'll have to find it. Pilot light = the generator is there but off; you just start it. Warm standby = a small generator already running, keeping some lights on. Multi-site = a second full supply already live — you never notice the cut.

5. Small things that get asked

  • Penetration testing — AWS permits pen-testing on 8 services without prior approval (EC2, RDS, CloudFront, Lambda and others). But DDoS simulation is not permitted without contacting AWS. The usual answer: "allowed without approval on the pre-approved services".
  • IAM Credentials Report = an account-level CSV listing every user and the state of their credentials. IAM Access Advisor = shows which services a user last accessed and when — used to strip unused permissions (least privilege).
  • IAM password policy = minimum length, requiring uppercase/numbers/symbols, password expiry and preventing reuse.
  • AWS Cost Anomaly Detection = uses machine learning to watch your spend and alerts you on unusual increases. The distinction: Budgets = you set the limit; Cost Anomaly Detection = AWS learns what normal looks like.
  • Service Control Policies (SCP) = in AWS Organizations, a restriction applied to a whole account or OU — it defines what simply cannot be done in that account. The key point: an SCP never grants permission, it only takes it away. If an SCP denies something, not even that account's administrator — or its root user — can do it. Example: "no account may use that Region".
  • VPC Flow Logs = a record of network traffic (who talked to whom) — for troubleshooting. VPC Peering = connecting two VPCs together. VPC Endpoint = reaching AWS services such as S3 over a private route, without going out to the internet.
