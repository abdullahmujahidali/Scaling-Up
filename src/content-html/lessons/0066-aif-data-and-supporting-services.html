The data services underneath the AI

The AIF exam does not only ask about AI services. Its official list has 49 services, and many are the data, storage and security services that run underneath a model. Eighteen of them appeared in none of my earlier lessons. The good news: they are all CLF services you already know. The only new thing here is what each one does in an AI context.

From I4: what does RAG do? Which is cheaper, fine-tuning or prompt engineering? And what is a hallucination?
RAG = find your own data first, then paste it into the prompt — no retraining. Prompt engineering is cheapest, fine-tuning most expensive. Hallucination = the model states something false with full confidence. Today: the services that hold all that data.

If you remember one thing Every AI project is a data project first. A model needs data that is stored (S3), cleaned (Glue), searchable (OpenSearch) and protected (KMS). The exam asks in exactly that order — so remember these services by their role in the AI pipeline, not as separate names.

1. The data journey: store → prepare → find

Everyday analogy Picture a restaurant kitchen. S3 is the store room holding raw ingredients. Glue is the person who chops, washes and prepares them. Glue DataBrew does the same job without writing code — point and click. Lake Formation is the lock and register on the store room: who may reach which shelf. Athena, Redshift and EMR are different ways of cooking. The chef (the model) only cooks well if the ingredients were cleaned.

2. Databases — the model's own memory

You know these from CLF. AIF only checks that you can pick the right one:

  • Amazon DynamoDB = fast NoSQL key-value. In AI apps, commonly used to hold chat history or session state.
  • Amazon DocumentDB = MongoDB-compatible, for JSON documents — and it can hold vectors too.
  • Amazon ElastiCache = in-memory cache (Redis/Memcached). Caching repeated answers is a standard way to cut inference cost.
  • Amazon MemoryDB = Redis-compatible but durable, so data survives a restart. It can also store vectors.
  • Amazon Kendra = AWS's intelligent search service. It answers natural-language questions over your internal documents (PDFs, SharePoint, S3), and gives you ready-made retrieval for RAG. Remember the split: OpenSearch = you manage the vectors yourself; Kendra = AWS does it for you.
  • Amazon S3 Glacier = very cheap archive storage. In an AI context: old training data or audit records you must retain but rarely touch. "Archive" or "rarely accessed" in a question means Glacier.
  • Amazon Neptune = a graph database for highly connected data (who is linked to whom).

3. Compute — where the model actually runs

Amazon EC2 (training on GPU instances), Amazon ECS and Amazon EKS (deploying a model inside containers). The exam wants no depth here — only that you know inference needs compute, and that SageMaker manages this for you.

The cost question AIF Domain 3 asks about cost. AWS Budgets = you set a limit and get alerted. AWS Cost Explorer = analyse spending that already happened. This matters in AI because inference costs accrue per call — more tokens, bigger bill.

The English of the exam A standard Domain 5 question: "the training data may contain personal information — what should be done first?" The answer is Macie (find it), then KMS (encrypt it). Remember the order: find first, then protect.

5. Transformer — the one word left out

Transformer is the architecture nearly every modern large language model is built on. Its key idea is attention: the model looks at every word in the input and decides which ones matter for the word it is producing. That is why it handles long sentences well. For the exam that is enough — the "T" in GPT stands for Transformer.
