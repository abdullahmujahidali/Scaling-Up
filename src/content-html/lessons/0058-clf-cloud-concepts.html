Cloud Concepts: why cloud, and how AWS thinks

This domain is more philosophy than technology — the benefits of cloud, the 6 Well-Architected pillars, and the money argument (CapEx vs OpEx). The questions are easy if you know the words and impossible if you don't.

If you remember one thing The whole cloud argument in one sentence: instead of paying a large sum up front and guessing, pay for what you use.

In English this is CapEx → OpEx:
CapEx (capital expenditure) = a big payment up front (buying servers). The data-centre way.
OpEx (operational expenditure) = ongoing running cost (billed by usage). The cloud way.

⭐ The exam uses AWS's own phrase "trade capital expense for variable expense" — it means exactly this.

The story: owning a car vs Careem

Buying a car: pay a large sum up front, then insurance, maintenance, parking — even when it sits idle. You must guess in advance: "I might occasionally need a big car" — so you buy big, and most of the time it sits unused.

Careem: nothing up front. A short trip takes a small car, a big load takes a big one. Need nothing? Pay nothing. That is cloud. And this difference is the root of every "benefit" question on the exam.

⭐ The benefits of cloud — in AWS's own words
  • ⭐ Trade capital expense for variable expense = no big up-front payment, only pay for use.
  • ⭐ Benefit from massive economies of scale = AWS buys for millions of customers at once, so it costs less, and that saving reaches you.
  • ⭐ Stop guessing capacity = no need to predict how many servers you'll need. Scale up or down on demand.
  • ⭐ Increase speed and agility = new resources in minutes, not weeks. Agility = the ability to change quickly.
  • Stop spending money running and maintaining data centers = the server room, power, cooling and guards become AWS's problem.
  • Go global in minutes = deploy to another country in a few clicks.
⭐ The three words people confuse
  • ⭐ Scalability = the ability to grow when needed.
  • ⭐ Elasticity = automatically growing and shrinking with demand. Not just up — down too. Auto Scaling provides this. "Automatically scales up and down" = elasticity.
  • ⭐ High availability = staying up despite failure → use multiple Availability Zones. Fault tolerance = no impact at all when something fails. Agility = being able to try new things quickly.

⭐ The Well-Architected Framework — 6 pillars

AWS's own framework for "what good design looks like". The exam asks which pillar covers what. Learn the six names and one line each:

PillarIn one lineThe clue in a question
Operational ExcellenceRunning and improving the system. Automation, monitoring, small frequent changes."processes", "automation", "run and monitor"
SecurityProtecting data and systems. IAM, encryption, least privilege."protect", "permissions", "encryption"
ReliabilityRecovering from failure and continuing to work. Backups, multi-AZ, recovery.⭐ "recover from failure", "backup", "availability"
Performance EfficiencyUsing resources efficiently — the right tool for the job."right instance type", "efficient use of resources"
Cost OptimizationRemoving unnecessary spend. Rightsizing, Reserved/Spot, shutting off waste.⭐ "reduce cost", "avoid unnecessary spend"
SustainabilityReducing environmental impact (energy, carbon). The newest pillar — hence asked."environmental impact", "carbon footprint"
Migration and cloud economics terms
  • ⭐ Rightsizing = matching resource size to actual need — shrinking an oversized server to save money. A key Cost Optimization term.
  • BYOL (Bring Your Own License) = bringing a licence you already own to AWS. The opposite: an included licence (bundled in the price).
  • Deployment models: Cloud (all in cloud), Hybrid (part cloud, part your own data centre), On-premises (all yours). "Keep some systems in our own data centre" = hybrid.
  • AWS Cloud Adoption Framework (CAF) = AWS's plan for moving to cloud. Benefits the exam lists: reduced business risk, improved ESG performance, increased revenue, increased operational efficiency.
  • AWS Snow Family = shipping very large data (terabytes+) on a physical device because uploading would take too long. "Petabytes" or "limited bandwidth" = Snow.
  • Migration tools: AWS DMS (migrating databases), AWS SCT (converting the schema when changing engine), Application Migration Service, Migration Hub (tracking it all).
Exam English — Domain 1 vocabulary "provision" = to create or set up a resource.
"elasticity" = expanding and contracting with demand.
"agility" = the ability to move and change fast.
"capital expense (CapEx)" = a large up-front cost. "variable/operational expense (OpEx)" = cost by usage.
"economies of scale" = buying in bulk makes it cheaper.
"rightsizing" = adjusting to the correct size.
"undifferentiated heavy lifting" = hard work everyone must do that gives no competitive advantage (racking servers) — AWS's pitch is that they'll do it.
"data sovereignty" = which country's laws govern the data.

Bridge to your work Rightsizing is a new word for something you already do. When you notice a Celery worker allocated 4 GB but using 500 MB, and shrink it — that's rightsizing.

Elasticity is what you wanted the time traffic spiked and you scaled instances by hand. Auto Scaling does it for you — and the exam's word is "elasticity", not "scalability", because it includes scaling *down*.

And the Well-Architected pillars? They're a code-review checklist for infrastructure. In a PR you ask: is it secure? is it fast? is it tested? AWS wrote the same questions into six boxes.
