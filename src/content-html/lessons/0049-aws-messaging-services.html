SQS vs SNS vs Kinesis: which one, when

All three are "sending messages" services, so the exam uses them as distractors for each other. One question separates them: how many readers does the message have, and can it be read again later?

If you remember one thing SQS = one message, one reader, gone once read.
SNS = one message, copied to everyone — instantly, then forgotten.
Kinesis = a river of data — many readers, and re-readable later (replay).

The words "replay", "re-process", or "analytics" in a question point only to Kinesis.

The story: three kinds of post

  • SQS = the office to-do box. A task slip goes into the box. Whichever worker is free picks it up, does the work, and tears the slip up. One slip = one person. No second worker can pick up that same slip. If a worker falls ill, the slip returns to the box for someone else.
  • SNS = the building loudspeaker. One announcement reaches everyone listening at that moment, all at once. Nothing is stored — whoever wasn't there missed it, and that's that.
  • Kinesis = a newsstand that also keeps back issues. The paper arrives daily, many people read it — and if you want last week's, it's still there (24 hours by default, extendable to 365 days). That's why "we need to re-process the data" points to Kinesis.

"distribute work", "workers process tasks", "decouple" SQS Each job should be done exactly once.
"one event, notify several systems", "fan-out" SNS Everyone needs their own copy.
⭐ "each subscriber needs its own queue with retries" SNS + SQS fan-out The exam's favourite pattern: one SNS topic → several SQS queues.
"real-time streaming", "replay", "analytics", "multiple consumers read the same data" Kinesis Data Streams The data persists and can be read repeatedly.
"preserve order" + "no duplicates" SQS FIFO Only FIFO gives ordering and exactly-once (300–3,000 msg/sec).
"route events between AWS services", "schedule", "events from a SaaS app" EventBridge Rule-based event routing; also does cron.
The messaging numbers the exam asks for
  • SQS message: max 256 KB. Bigger → store in S3 and send a pointer (the Extended Client Library).
  • SQS retention: 4 days default, 14 days max. Minimum 60 seconds.
  • Visibility timeout: 30 seconds default, 12 hours max. ⭐ If a message is being processed repeatedly (duplicate work), the answer is to raise the visibility timeout — the message is reappearing before the worker finishes.
  • Long polling: max 20 seconds. ⭐ Almost always the answer to "reduce SQS costs" (it cuts empty receive requests).
  • Kinesis shard: 1 MB/s in, 2 MB/s out. Retention 24 hours by default, up to 365 days.
  • SQS FIFO: 300 msg/sec (3,000 with batching). Standard queue: unlimited.
Trap — a Standard queue can deliver duplicates An SQS Standard queue gives "at-least-once" delivery — a message can occasionally arrive twice, and ordering isn't guaranteed. If a question says "the payment was processed twice", two answers are possible: a FIFO queue (if ordering matters too) or idempotent processing (code that's safe to run twice). If the question says "no code changes", pick FIFO; if it says "high throughput required", pick idempotency, because FIFO is slower.
Exam English — messaging words "decouple" = separate two parts so one failing doesn't take the other down (this word points to SQS almost every time). "fan-out" = send one thing to many places. "poll" = repeatedly ask "is there anything?". "dead-letter queue (DLQ)" = where repeatedly-failing messages go so they can be inspected separately. "idempotent" = doing it twice gives the same result as doing it once.

Bridge to your Django work SQS is exactly your Celery + Redis/RabbitMQ. You push a task, one worker picks it up, runs it, done. The visibility timeout is precisely Celery's visibility_timeout — including the same bug: if the task returns to the queue before the worker finishes, it runs twice. You've probably hit this in production. SNS is Django signals — an event fires, several receivers hear it, nothing is stored. Kinesis has no direct Django equivalent — it's Kafka-like, and you already did that lesson (0025).
From memory: a message is being processed twice and processing takes 90 seconds — what do you raise? And which service does the word "replay" point to?
The visibility timeout (the default is 30 seconds while processing takes 90 — which is exactly why the message reappears). "Replay" = Kinesis, because only it retains the data.
