Recursion: a function that calls itself on a smaller problem

Break a big problem into a smaller version of the same problem, until it's small enough to answer directly.

~8 min One concept: recursion Win: read code that calls itself without panicking

30-second warm-up (recall tree structures)

From memory: what is a tree, and what are its "children" themselves?
A tree is a nested structure — a node has children, and each child is itself a smaller tree. Folders inside folders, replies under a comment, a team under an org chart. That "same thing inside itself" shape is exactly what recursion is built for — which we're about to see.

If you remember one thing Recursion = a function that calls itself on a smaller version of the same problem, until it hits a "base case" — the simplest version it can answer directly. Two must-haves: a base case (when to STOP) and a recursive step (call itself on something smaller).

The story: Russian nesting dolls (matryoshka)

You have a matryoshka — that wooden doll that opens to reveal a smaller doll inside. You want to open them all. You have exactly one rule: "Open a doll. If there's a smaller doll inside, do the same exact thing to it. If the doll inside is the tiny solid one that doesn't open — stop."

Notice: you don't invent a new rule per doll. You apply one rule again and again to a smaller thing. The tiniest solid doll is your base case — that's where you stop. Every other doll's "open this, then do the same to the one inside" is the recursive step. That's recursion.

Another picture: you stand in a queue and want your position number. You ask the person in front "what number are you?" — who asks the person in front of them — until the very first person (the base case) says "I'm 1." Then the answer travels back down the queue, each person adding 1. Same one question, repeated on something smaller.

In code: factorial

The most classic example — factorial(n), i.e. n × (n-1) × ... × 1. Notice how both must-haves show up:

def factorial(n):
    if n == 1:          # base case — when to STOP
        return 1
    return n * factorial(n - 1)   # recursive step — call itself on n-1

factorial(4)  # 4 * factorial(3) → 4 * 3 * factorial(2) → ... → 24
  • Base case: if n == 1: return 1. The simplest version, answerable without another call. This is what makes it stop.
  • Recursive step: return n * factorial(n - 1). The function calls itself on a smaller input (n-1) — moving toward the base case.
Django bridge You've probably used this in Python without naming it. Walking a nested folder tree, flattening nested JSON, or rendering threaded comments (replies under a comment, more replies under a reply) — these are all natural recursion, because the data is itself nested. In DRF a self-referencing serializer (a comment whose children are comments) is recursion. But a warning: Python has a recursion limit of ~1000. If your nesting is very deep (or you accidentally miss the base case), you get RecursionError: maximum recursion depth exceeded — because every call takes memory on the call stack and it overflows. For very deep or large data a plain loop (or an explicit stack/queue) is often better and safer.
Quick check: what happens if you forget the base case, or it's never reached?
The function keeps calling itself forever — it never stops. Each call adds a new frame on the stack, memory runs out, and you get a stack overflow (in Python, a RecursionError). The base case is "when to stop" — without it, recursion is an infinite loop.

The tradeoff — name it in interviews Recursion is elegant for nested/tree data — the code matches the shape of the data and reads cleanly. But every call uses call-stack memory, deep recursion can stack overflow, and it isn't always the fastest. Interview line: "Recursion is clean for tree-shaped data, but I watch stack depth on deep inputs — I'll use a loop or an explicit stack if needed."
What are the two must-have parts of a recursive function?
Your recursive function throws RecursionError: maximum recursion depth exceeded on a very deep nested structure (10,000 levels). Most likely cause and fix?
Your win today Recursion: a function that calls itself on a smaller version of the same problem. Two parts — a base case (when to stop) and a recursive step (call on something smaller). Without a base case it never stops → stack overflow. It's natural for nested/tree data (folders, JSON, threaded comments) but spends call-stack memory — so on deep inputs a loop is sometimes better.
