Lambda's limits: the 15-minute rule

Lambda has many numbers, but the exam uses only a few as decision-makers. The most important: 15 minutes. That single number flips the answer to entire questions.

~8 min One concept: when Lambda is the WRONG answer Win: instantly eliminate 2 options
First, recall from A1: a question says "LEAST operational overhead". What do you lean toward, and what do you run from?
Lean toward: managed/serverless — Lambda, Fargate, DynamoDB, S3, SQS. Run from: anything where you patch or scale EC2. Today we add a condition to that: when Lambda is wrong despite being serverless.
click to reveal — say it out loud first
If you remember one thing Lambda cannot run longer than 15 minutes. Full stop. No setting, no trick, no amount of money changes it. The moment a question describes work taking longer than 15 minutes, every Lambda option is instantly wrong, however good it looks. Its replacement is Fargate (serverless, no time limit) or Step Functions (for long workflows).

The story: a parking meter

Imagine a parking meter that accepts a maximum of 15 minutes. The sign says "maximum 15 minutes". However many coins you have in your pocket, however much you're willing to pay — the machine will not accept more than 15. If you need to park for 45 minutes, this spot is simply not for you. You must find another one, no matter how close or cheap this one is.

Lambda is that parking meter. And here's the exam's trap: it offers you an option saying "configure the Lambda function with a 45-minute timeout" — which is a lie; that setting cannot exist. AWS includes it deliberately, because people who don't know the 15-minute rule will pick it.

The Lambda numbers the exam asks for
  • ⭐ Timeout: 900 seconds = 15 minutes (maximum). The default is only 3 seconds — that gets asked too. Longer work = Fargate.
  • Memory: 128 MB to 10,240 MB (10 GB). Key point: you cannot set CPU separately — raising memory raises CPU with it. 1,769 MB = exactly 1 vCPU. This is why "the function is slow" is often answered by "increase memory".
  • /tmp disk: 512 MB (default) up to 10,240 MB. This matters when a question says "download and process a large file".
  • Payload: 6 MB synchronous, 256 KB asynchronous. For bigger data, put the file in S3 and pass only the pointer — a favourite exam answer.
  • Deployment package: 50 MB zipped, 250 MB unzipped (including layers). Container image: 10 GB. Hence a large ML model = container image.
  • Environment variables: 4 KB total. This is why large secrets belong in Secrets Manager.
  • Concurrent executions: 1,000 per region (default; can be raised). Layers: 5 per function.
The biggest trap — API Gateway's 29 seconds Lambda can run 15 minutes — but if API Gateway is calling it, only 29 seconds. API Gateway cuts the connection at 29 seconds even though Lambda keeps running. The exam asks it like this: "the API returns 504 Gateway Timeout" — and the answer is not to raise the Lambda timeout; it's to make the work asynchronous (push the request to SQS, or return 202 immediately and process in the background). This pair of numbers — 15 minutes and 29 seconds — is asked a lot.

Reserved vs Provisioned concurrency — memorise this pair

These two names sound alike and AWS deliberately offers both. The difference is clean:

SettingWhat it doesWhen it's the answer
Reserved
= a cap		 Reserves slots for one function — and also caps it there. One setting, two effects. "One function is eating everyone's concurrency", or "protect the database from overload". Does NOT fix cold starts.
Provisioned
= pre-warmed		 Keeps environments pre-warmed and ready. You pay even with zero requests. ⭐ Any mention of "cold start" or "consistent low latency" = this, always.
Exam English — words that appear in Lambda questions "cold start" = the extra delay when a function starts for the first request. "throttled" = the request was rejected because the concurrency limit was hit (error: TooManyRequestsException, 429). "times out" = ran out of time. "invoke" = to call the function. "ephemeral" = temporary, disappears (hence /tmp is called "ephemeral storage" — it may not be there next time).

Domain 4 · Troubleshooting · two numbers at once

A reporting Lambda function is invoked through API Gateway. The function takes about 90 seconds to complete, but users receive a 504 Gateway Timeout. CloudWatch shows the function completing successfully. What is the best fix?

Bridge to your Django work You already make this decision routinely. In Django, when work takes too long inside a request — generating a PDF, sending email, processing a big file — you push it into a Celery task, because the browser and gunicorn have their own timeouts. API Gateway's 29 seconds is exactly your gunicorn timeout, and the "make it asynchronous" answer is exactly your Celery decision. Only the names differ: Fargate/SQS instead of a Celery worker. You know this concept — only the AWS words are new.
From memory, without scrolling up: Lambda's max timeout? API Gateway's timeout? And the cold-start cure — Reserved or Provisioned?
Lambda: 900 seconds = 15 minutes. API Gateway: 29 seconds. Cold start = Provisioned concurrency (Reserved only sets a cap). If you got all three, you have this lesson's real value.
