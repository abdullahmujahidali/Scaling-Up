Two-pointer & sliding window: turn O(n²) into O(n)

The #1 pattern for array/string interview questions — it replaces a nested loop with a single scan.

~8 min One concept: scan once, don't redo work Win: kill an O(n²) brute force

30-second warm-up (recall Big-O)

From memory: a nested loop over a list (loop everything for each element) is which Big-O, and a single scan is which?
Nested loop = O(n²) — ~1 million steps at 1,000 rows, and it dies fast. Single scan = O(n) — just 1,000 steps at 1,000 rows. Today we learn a trick that drops many O(n²) problems down to O(n).

If you remember one thing Instead of two nested loops, walk the data just once — using two markers (pointers) or one growing/shrinking window. Move the work forward at each step; never re-check what you already checked. That's the whole "don't redo work you've already done" idea.

The story: a bookshelf and a train window

Think of two-pointer like this: a long bookshelf that's sorted by title, and two people — one at the far left edge, one at the far right edge. They need to find a pair of books whose page-counts add up to a target. Left stands on a low-page book, right on a high-page book. If their total is too big, right steps inward (toward smaller). If it's too small, left steps inward. They meet in the middle — the whole shelf walked exactly once, never twice.

Sliding window is different: picture looking out the window of a moving train. The frame (window) slides along the landscape. You let a new tree enter the window (you expand the window forward), and you never look again at what already passed behind you. If a rule breaks (say "nothing may repeat inside the window"), you shrink the frame a little from the back edge until the rule holds again.

Two concrete examples

  • Two-pointer — "find two numbers in a sorted list that add up to a target": put one pointer at each end. If the sum is bigger than the target, move right pointer left (sum shrinks); if smaller, move left pointer right (sum grows); match found means done. O(n), versus a nested loop's O(n²).
  • Sliding window — "longest stretch with no repeated character": grow the window forward, taking each new character in. The moment a character repeats inside the window, advance the back edge until the duplicate is gone. Keep tracking the best length. One pass, no re-checking everything — O(n).
Python bridge This ties straight into the Big-O and N+1 lessons. Ever accidentally wrote a nested loop over a list — for a in items: for b in items: ...? That's O(n²) and dies at a few thousand rows. If the data is sorted (or you can sorted() it), two pointers do the same job in one O(n) pass. Realistic spot: log processing or stream scanning — say "most errors in any 5-minute window." Feed each new log line into the window, and as soon as the window spans more than 5 minutes, drop lines off the back. One pass over the whole file, never revisiting earlier lines. Same idea, real backend work.
Quick check: what does the list usually need to be for the two-pointer "two-sum" to work?
Sorted. Because the decision "sum too big → move right inward" or "too small → move left inward" only works when elements are in order. If it isn't sorted, you sort first (O(n log n)) — which is often still better than a nested loop.

The tradeoff — name it in interviews It doesn't fit every problem. Two-pointer usually needs sorted data (or the O(n log n) cost to sort it); sliding window needs a clear rule that breaks as the window grows and recovers as it shrinks (like "no repeats" or "sum ≤ K"). If order doesn't matter and there's no clean monotonic window rule, the pattern doesn't apply — a hash-map or something else fits better. But when it does fit, O(n²) → O(n) is a huge jump. In an interview: first ask "is it sorted / is there a clean window rule?" — that's the senior signal.
You need to find two numbers in a sorted list that add up to a target. The fastest clean approach?
"Longest substring with no repeated character" — when a character repeats inside the window, what do you do?
Your win today You can spot a nested loop and replace it with a single scan: two-pointer (both ends inward on sorted data) or sliding window (one frame that expands and shrinks). Both turn O(n²) into O(n) because you don't redo work already done. This is the #1 pattern for array/string interview questions — and saying "this could be two-pointer/sliding-window" in an interview is a strong signal.
